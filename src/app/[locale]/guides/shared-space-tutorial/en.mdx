In this tutorial, you'll build a shared calendar on atproto. One account hosts the calendar as a Space, adds friends as members, and everyone can post events and RSVP to them. Each person's events and RSVPs are stored in their own repo on their own PDS, and your app syncs all of them into one view with [jetstream-spaces](/guides/space-sync). You'll use the same [Lexicon Community](https://lexicon.community/) calendar [Lexicons](/guides/lexicon) as in [Build a Private App](/guides/private-app-tutorial), along with the Spaces TypeScript SDK and [OAuth](/guides/auth).

It works the same way as the sync diagram in the [Spaces walkthrough](/guides/spaces#jetstream-for-spaces), with an event and an RSVP in place of a ride and a cheer:

## Prerequisites

You should have installed:

- Node.js 22+
- Go

On platforms supported by [homebrew](https://brew.sh), you can install them with:

```bash
brew install node go
```

You'll also need two accounts on a *PDS that supports Spaces*: one to host the calendar, and one for a friend. As of December 1, 2026, the [reference PDS](https://github.com/bluesky-social/pds) includes support for Spaces.

Lastly, you'll need a public HTTPS address, so that the PDS hosting your calendar can notify it when anyone writes to the calendar. For local development, you can use a tunneling service like [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/), [ngrok](https://ngrok.com/docs/), or [Tailscale Funnel](https://tailscale.com/kb/1223/funnel).

## Part 4: OAuth and the controller

Now you'll need to create some OAuth boilerplate. Create a new file at `src/sync.ts` with these contents:

<S05 />

There are two things going on here. One is an OAuth client, as in [OAuth with Node.js](/guides/oauth-cli-tutorial). It requests two [permission scopes](/guides/permission-requests): base `atproto`, and a `space:` scope for calendars: `authority=*` to read and write in any calendar the user is a member of, `manage=create` to create one, and `manage=update` to add members.

The other is a `SpaceSyncController` that connects your app to `jetstream-spaces`. It tells `jetstream-spaces` which space to sync, and when `jetstream-spaces` needs access, it uses a signed-in user's OAuth session to get it, starting with the host.

This app stores sessions in memory, so restarting it signs everyone out. A production app should store them durably, since `jetstream-spaces` will keep asking for access.
