このチュートリアルでは、atproto上に共有カレンダーを構築します。1つのアカウントがカレンダーをスペースとしてホストし、友人をメンバーとして追加します。メンバーは誰でもイベントを投稿し、出欠の返信（RSVP）ができます。各人のイベントとRSVPはそれぞれのPDS上の自分のリポジトリに保存され、アプリは[jetstream-spaces](/guides/space-sync)を使ってそれらすべてを1つのビューに同期します。[プライベートアプリを作る](/guides/private-app-tutorial)と同じ[Lexicon Community](https://lexicon.community/)のカレンダー用[Lexicon](/guides/lexicon)を、SpacesのTypeScript SDKおよび[OAuth](/guides/auth)と組み合わせて使用します。

仕組みは[Spacesの解説](/guides/spaces#jetstream-for-spaces)にある同期の図と同じで、ライドとチアの代わりにイベントとRSVPを扱います。

## 前提条件

以下をインストールしておいてください。

- Node.js 22以上
- Go

[homebrew](https://brew.sh)に対応したプラットフォームでは、次のコマンドでインストールできます。

```bash
brew install node go
```

また、*Spacesに対応したPDS*上のアカウントが2つ必要です。1つはカレンダーをホストするためのもの、もう1つは友人役のものです。2026年12月1日時点で、[リファレンスPDS](https://github.com/bluesky-social/pds)はSpacesに対応しています。

最後に、誰かがカレンダーに書き込んだときに、カレンダーをホストするPDSから通知を受け取れるよう、公開HTTPSアドレスが必要です。ローカル開発では、[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/)、[ngrok](https://ngrok.com/docs/)、[Tailscale Funnel](https://tailscale.com/kb/1223/funnel)などのトンネリングサービスを利用できます。

## パート4：OAuthとコントローラー

次に、OAuthの定型コードを作成します。`src/sync.ts`に次の内容で新しいファイルを作成します。

<S05 />

ここでは2つのことを行っています。1つはOAuthクライアントで、[Node.jsでのOAuth](/guides/oauth-cli-tutorial)と同様のものです。2つの[パーミッションスコープ](/guides/permission-requests)を要求します。基本の`atproto`と、カレンダー用の`space:`スコープです。`space:`スコープでは、ユーザーがメンバーになっている任意のカレンダーを読み書きするための`authority=*`、カレンダーを作成するための`manage=create`、メンバーを追加するための`manage=update`を指定しています。

もう1つは、アプリを`jetstream-spaces`に接続する`SpaceSyncController`です。これは`jetstream-spaces`にどのスペースを同期するかを伝え、`jetstream-spaces`がアクセスを必要とするときには、ホストから順に、サインイン済みユーザーのOAuthセッションを使ってアクセスを取得します。

このアプリはセッションをメモリに保存するため、再起動すると全員がサインアウトされます。`jetstream-spaces`は継続的にアクセスを要求するため、本番アプリではセッションを永続的に保存すべきです。

## パート5：イベントとRSVPのインデックス作成

次に、ブロードキャストされる通知を処理するために、`src/indexer.ts`に別のファイルを作成します。

<S06 />

これは`jetstream-spaces`から読み取り、カレンダーをメモリ上に保持します。
- `.commit()`は、イベントやRSVPの書き込みと削除を処理します。
- `.space()`と`.account()`は、レコードがスペースから消えるその他のケースを処理します。スペースの削除、作成者の削除、アカウントの無効化または削除です。これらはすべて必須です。
- `startIndexer()`は、すべてを最初からリプレイし、その後は到着する新しいイベントを追跡します。
